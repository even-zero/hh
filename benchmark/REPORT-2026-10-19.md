# Executor benchmark rerun — 2026-10-19

**Outcome: discovery gap closed for the five benchmark repositories; large-suite overhead improved but the 2% gate is still missed.** This is a fresh run after clearing generated records, logs, stores and results. Raw aggregated measurements: [reports/2026-10-19-results.json](reports/2026-10-19-results.json); [baseline comparison](reports/2026-10-19-compare.md). Commands: `python3 -m benchmark setup`, `python3 -m benchmark run`, `python3 -m benchmark collect`, `python3 -m benchmark dashboard`, `python3 -m benchmark compare`.

## Changes measured

- `hh plan` now collects pytest's **post-deselection** node IDs, Mocha's default `test/*` universe and both unittest `test_*.py`/`*_test.py` layouts. pytest and Mocha have selectable streaming executors; shard selections go through files instead of overflowing argv on large suites. Normalized-key collisions are disambiguated so inherited tests cannot disappear.
- Python ledger output keeps one append descriptor per process and writes complete rows with a single append syscall. For pytest's many tiny tests, completed tests write an end row; a 20 ms watchdog writes a start row for a test that remains active, so a hanging test is still named on a hard kill. The executor's children now stay in the harness's process group, preventing an externally killed parent from leaving a child continuing to write/re-execute during resume. Durations use `CLOCK_MONOTONIC` to survive freezegun's clock patches; pytest setup skips produce terminal rows.

**The overhead shortfall is not solved.** The improvement eliminates most start rows and file open/close operations, but the synchronous per-test pytest hook/serialization path still adds ~3.86 s on this ~30 s suite. Do not claim the E1 ≤2% gate passed. Further work needs a lower-cost checkpoint protocol or a revised, explicitly measured durability/latency trade-off. With a 20 ms start grace, a kill in the first 20 ms of an in-flight test can leave no open interval for that particular test; every test that has already completed still has its end checkpoint.

Native execution on subsecond suites has significant *startup-inclusive* cost versus a bare pytest/Mocha process: 58% itsdangerous, 48% markupsafe and 18% chai when planning is included. These are **not comparable to the old capture-only overhead percentages** and are deliberately omitted from the like-for-like capture comparison. Small-suite execution and pytest/Mocha fixture isolation across shards remain areas to measure before recommending W>1 generally.

## Method and reproducibility

Pinned refs are in `benchmark/repos.json`; this environment used Python 3.11.2, Node 22.22.3 and two CPUs; the frozen baseline used Python 3.13 and Node 20, so percentage changes are directional, not controlled A/B estimates. Existing sitecustomize and shim rules were retained. `python3 -m unittest discover -s tests -q`: 43 passed, including native discovery, setup-skip selection, and SIGKILL hang-name regressions. The benchmark's downloaded repositories and generated hang variant were removed after collection; the small aggregated JSON and this report are retained. Recreate the full run with `python3 -m benchmark setup && python3 -m benchmark run && python3 -m benchmark collect`.
